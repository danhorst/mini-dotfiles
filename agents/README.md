# Shared agent memory

A harness-agnostic memory corpus and engine, meant to be reused by more than one AI coding harness in this repo (currently: Claude Code, via `../claude/bin/memory`).

## Layout

```
memory/       cemented memory seeds (markdown + YAML frontmatter)
bin/memory    the seed/cement/lint engine
```

## Seeds

Each seed is a markdown file with frontmatter:

```yaml
---
name: <display name; kebab-cased, used as the [[wikilink]] target>
description: <one-line summary, shown in the index>
metadata:
  type: user|reference|project|feedback   # required
  cement: false        # optional — marks a templated seed; `memory cement` refuses to overwrite it
  originSessionId: <uuid>   # optional — a stale-live signal during triage
---
```

Body is freeform markdown.
Cross-references use `[[wikilink]]` tokens that must resolve to some other seed's kebab-cased `name`.

Write seeds from the *consuming agent's* runtime point of view, not the dotfiles maintainer's tree view — a seed materialized into a harness's live memory dir has no line of sight into this repo's file layout, so don't reference paths like `claude/etc/` or `bin/tool-prefs-check.sh` from seed content.

`MEMORY.md` is a generated index (`- [name](file.md) — description`, grouped by type) — regenerated by `memory index`, never hand-edited.

## The engine (`bin/memory`)

Bash, depends only on `rg`, `jq`, `envsubst`, `git`, `cmp`.
Not on `PATH` directly — a harness-specific adapter resolves paths and delegates to it (see `../claude/bin/memory` for the reference implementation).

Subcommands:

```
seed                 Populate the live memory dir from cemented seeds (non-destructive)
cement <file…>       Promote live files to the cemented seeds, regenerate the index, stage the result
resync <file…>       Mirror cemented seeds back over their live copies (inverse of cement)
resync --all-stale   Resync every live file that differs from its seed (overwrites live with seed)
index                Regenerate MEMORY.md from seed frontmatter
lint                 Validate seed frontmatter, index membership, and [[wikilinks]]
fix                  Auto-fix table shape and index membership (mechanical subset of lint)
triage               Report live-vs-cemented divergences
```

## Adapter contract

A harness wires itself up by setting two environment variables and delegating to this script:

- `MEMORY_SEEDS_DIR` — required by every subcommand. Point it at `memory/` in this directory.
- `MEMORY_LIVE_DIR` — required by `seed`, `cement`, `resync`, and `triage`. The harness's own per-project "live" working-copy directory, materialized from seeds and freely edited during a session until deliberately promoted back. `index`, `lint`, and `fix` operate on the seed corpus alone and don't need it.

`../claude/bin/memory` is the reference adapter: it resolves `MEMORY_SEEDS_DIR` relative to the `~/.claude/commands` symlink (never a hardcoded checkout path) and sets `MEMORY_LIVE_DIR` to Claude Code's per-project memory convention (`~/.claude/projects/<encoded-cwd>/memory/`), then `exec`s this script.
A new harness needs its own equivalent: a place to resolve this repo's checkout path dynamically, and a notion of a per-project (or equivalent) live working copy — a hook or command to call `memory seed`/`memory triage` at the right moments.
